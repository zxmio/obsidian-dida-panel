# 滴答面板 AI 对话框方案

目标：在滴答清单任务面板底部加一个常驻对话框，用自然语言让 AI 创建、修改、删除、查询滴答待办。AI 通道照 MakerPilot 的做法，用本机 Claude Code 的登录态，不另配密钥。

## 一、结论先行

- **通道**：`@anthropic-ai/claude-agent-sdk`（MakerPilot 同款 0.3.293）在插件进程内拉起本机 Claude Code。
- **滴答工具**：插件已经持有滴答 MCP 的 OAuth 令牌，直接以 HTTP 型 MCP 挂给 SDK（`mcpServers.dida365 = {type:"http", url, headers:{Authorization}}`）。不依赖 Claude Code 自己的 MCP 配置，Obsidian 里登录一次两边都通。
- **移植范围**：只搬 MakerPilot 里「Electron 里找 node、找 claude、拉进程」的运行时胶水，约 400 行；UI、多 provider 抽象、消息归一化一概不搬。
- **首版只做 Claude**。Codex / Gemini 以后若要，走 MakerEditor 方案里定的「给 MakerPilot 加公开 API」路线，不在本插件重做。

## 二、为什么不是另外两条路

| 路线 | 放弃原因 |
|---|---|
| 插件直接调 Claude API | 要新密钥、按 token 计费，滴答工作区约定还得重喂一遍 |
| 后台 `claude -p` 子进程 | 和 SDK 走的是同一个二进制，但拿不到权限回调和流式事件，删除类操作没有硬门禁 |
| 复用 MakerPilot | 它没有「发一段话拿回结果」的接口，只能往它输入框填字 |

## 三、新增依赖及理由

| 依赖 | 理由 |
|---|---|
| `@anthropic-ai/claude-agent-sdk@0.3.293` | 官方 SDK，唯一能用 Claude 订阅登录态跑带 MCP 工具的 Claude Code 的方式；锁 MakerPilot 同版本，打包坑它已踩平 |
| `cross-spawn` | 与 MakerPilot 一致，Windows 下 `.cmd` shim 才能拉起 |

打包：复制 MakerPilot `esbuild.config.mjs` 里两个针对 SDK 的插件（修 `import.meta.url`、剔除未用的 zod / MCP peer），`external` 加 Node 内置模块。

## 四、对话框形态

- 面板底部固定一块：多行输入框（自适应高度，⌘↩ 发送，Esc 中止当前回合）；输入框上方是可折叠的对话区，默认收起只露最后一句，点开看全程。
- 对话区里三种条目：你的话、AI 的回复（Markdown 渲染）、工具步骤行（「查今天的任务 ✓」「已创建：写一篇文章介绍MakerOS」「等待确认：删除 3 条」）。
- 每回合结束自动刷新面板（总览、今天、当前项目）。
- 「新对话」按钮清空并丢弃 session；否则用 `resume` 续接，能说「刚才那条改到周五」。
- Claude Code 没装或没登录：对话区显示原因和修法，输入框禁用。

## 五、权限与安全

- `allowedTools`：滴答查询类、`create_task`、`update_task`、`complete_task`、`create_tag` 自动放行；`Read` / `Grep` / `Glob` 放行（读 vault 笔记当上下文）。
- `canUseTool` 弹 Obsidian 确认框（列出要动的任务标题）：`delete_task`、`batch_add_tasks`、`batch_update_tasks`、`complete_tasks_in_project`、`move_task`、`delete_tag`、`delete_project_group`、`update_project`、`create_project`。
- `disallowedTools`：`Bash`、`Write`、`Edit`、`MultiEdit`、`NotebookEdit`、`WebFetch`、`WebSearch`。这个对话框只管滴答，不动文件。
- 系统提示里再写一遍：批量、删除、跨项目移动前先列清单问我。
- **不加载全局 Claude 设置**：`settingSources` 不含 `user`，Claude Code 不会把 `~/.claude` 里的其它 MCP（Supabase、Gmail、飞书等）和 hooks 带进这个会话，只挂插件给的滴答 MCP。这是防提示注入最关键的一道。
- 一回合内 `update_task` 超过 5 次，第 6 次起也走确认。

## 五之二、账号安全说明

- SDK 拉起的是本机 Claude Code 程序，登录态由它自己从系统钥匙串读；插件不读、不存、不转发任何令牌，与终端里运行 `claude` 风险面相同（MakerPilot 亦然）。
- 走官方 Agent SDK，不是把 Claude Code 的 OAuth 令牌拿去直调 API，符合 Anthropic 的使用边界。
- 对话消耗的是 Claude 订阅额度。

## 六、系统提示要带的上下文

- 工作区约定：收件箱查询用 `inbox`、看板移列只传 `columnId`、日期必须带时区、优先级只有 0/1/3/5、标签整体覆盖先读再合并、`complete_task` 而不是改 status。
- 实时上下文：当前页签、当前项目与列（名称和 id）、展开的那条任务 id、当前打开的笔记路径与 vault 名、今天的日期和时区。
- 卡片格式约定（正文 / 来源深链）。

```

```

## 八、验收

1. 面板底部输入「把今天过期的三条都推到明天」→ AI 调 `filter_tasks` 后逐条 `update_task`，面板刷新后今天视图过期组清空。
2. 输入「删掉收件箱里标题含测试的任务」→ 弹确认框列出标题，取消则不删。
3. 输入「在内容创作的选题池加一条：Obsidian 滴答插件复盘，标签公众号」→ 新卡片出现在选题池，标签正确。
4. 关掉 Claude Code 登录 → 对话区显示未登录提示，不报错崩面板。

## 九、不做

- 对话历史持久化（关面板即丢，session id 存内存）。
- 让 AI 改笔记文件。
